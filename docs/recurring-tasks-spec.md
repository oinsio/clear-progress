# Повторяющиеся задачи — Спецификация

## 1. Обзор

Повторяющиеся задачи позволяют автоматически создавать новые экземпляры задач по расписанию или после завершения предыдущего экземпляра. Задача-клон создаётся **сразу** при завершении предыдущей и хранится в скрытом состоянии до наступления расчётной даты появления.

---

## 2. Два типа повторения

### 2.1. Fixed (фиксированное расписание)

Следующая задача появляется **строго по расписанию**, независимо от того, когда была завершена предыдущая.

Примеры: ежедневный обзор задач, еженедельное планирование по понедельникам, оплата коммуналки 23-го числа каждого месяца, ежегодная прививка кошке.

### 2.2. After Completion (после завершения)

Следующая задача появляется **через N дней после завершения** предыдущей.

Примеры: полить цветы через 4 дня после полива, парикмахерская через 3 недели после стрижки.

---

## 3. Модель данных

### 3.1. Поле `repeat_rule` в Tasks

Хранится как **JSON-строка** в одной ячейке таблицы Tasks в Google Sheets.

```typescript
interface RepeatRule {
  // --- Тип повторения ---
  type: "fixed" | "after_completion";

  // --- Для fixed ---
  frequency?: "daily" | "weekly" | "monthly" | "yearly";
  interval?: number; // каждые N (дней/недель/месяцев/лет), >= 1
  weekdays?: number[]; // для weekly: дни недели, 1=Пн ... 7=Вс
  day_of_month?: number; // для monthly: число месяца, 1-31
  month_and_day?: {
    // для yearly
    month: number; // 1-12
    day: number; // 1-31
  };

  // --- Для after_completion ---
  delay_days?: number; // через сколько дней после завершения, >= 1

  // --- Общее ---
  target_box: "today" | "week" | "later"; // в какую коробку поместить
  advance_days: number; // за сколько дней до расчётной даты
  // показать задачу (0 = в день даты)
}
```

### 3.2. Новые поля в Tasks

| Поле               | Тип                          | Описание                                                                  |
| ------------------ | ---------------------------- | ------------------------------------------------------------------------- |
| `repeat_rule`      | string (JSON)                | Правило повторения. Пустая строка = не повторяется                        |
| `is_hidden`        | boolean                      | `true` = задача-клон ожидает наступления `appear_date`                    |
| `next_date`        | string (ISO 8601, date only) | Расчётная дата следующего срабатывания                                    |
| `appear_date`      | string (ISO 8601, date only) | Дата появления = `next_date` − `advance_days`                             |
| `original_task_id` | string                       | ID оригинальной задачи для скрытых копий. Пустая строка для обычных задач |

### 3.3. Обновлённая структура Tasks

```
id, title, notes, box, goal_id, context_id, category_id,
is_completed, completed_at, repeat_rule, is_hidden, next_date, appear_date,
original_task_id, sort_order, is_deleted, created_at, updated_at, version
```

## 4. Механика работы

### 4.1. Завершение повторяющейся задачи

При завершении задачи с `repeat_rule`:

1. Текущая задача помечается `is_completed: true`, `completed_at: <now>`.
2. Вычисляется `next_date` для следующего экземпляра (см. раздел 5).
3. Вычисляется `appear_date = next_date − advance_days`.
4. **Проверка на существующую скрытую копию:**
   - Определяется `searchId = task.original_task_id || task.id`
   - Ищется существующая скрытая копия по `original_task_id = searchId`
   - Если найдена — обновляется (см. 4.1.1)
   - Если не найдена — создаётся новая (см. 4.1.2)
5. Если у задачи есть **чеклист** — пункты чеклиста копируются с `is_completed: false`.

#### 4.1.1. Обновление существующей скрытой копии

Если скрытая копия уже существует (задача была возвращена в незавершённое состояние), она обновляется:

- `name`, `description`, `goal_id`, `context_id`, `category_id` — актуальные значения из завершаемой задачи
- `repeat_rule` — актуальное правило
- `next_date`, `appear_date` — пересчитанные значения
- `box: target_box` из `repeat_rule`
- `original_task_id` — **НЕ меняется**
- `updated_at: <now>`, `version += 1`

#### 4.1.2. Создание новой скрытой копии

Если скрытой копии не существует, создаётся **задача-клон** с:

- Новый `id` (UUID v4)
- `title`, `notes`, `goal_id`, `context_id`, `category_id` — копируются из оригинала
- `repeat_rule` — копируется из оригинала
- `box: target_box` из `repeat_rule`
- `is_completed: false`
- `is_hidden: true`
- `next_date`, `appear_date` — вычисленные значения
- `original_task_id: task.original_task_id || task.id` — наследуется или устанавливается
- `sort_order: 0` (будет в начале списка при появлении)
- `is_deleted: false`
- `created_at: <now>`, `updated_at: <now>`, `version: 1`

### 4.2. Раскрытие скрытых задач

При каждом открытии приложения и периодически (при pull-синхронизации) выполняется проверка:

```
Для каждой задачи где is_hidden = true И is_deleted = false:
  Если текущая_дата >= appear_date:
    is_hidden = false
    box = target_box (из repeat_rule)
    original_task_id — НЕ меняется (остаётся как есть)
    updated_at = <now>
    version += 1
```

**Важно:** При раскрытии задачи поле `original_task_id` сохраняет своё значение. Это обеспечивает связь всех копий в цепочке повторений.

### 4.3. Незавершённая задача с фиксированным расписанием

Если задача с `type: "fixed"` не была завершена к моменту `next_date`:

- Задача просто остаётся в текущей коробке и ждёт завершения.
- При завершении `next_date` вычисляется **от оригинального расписания**, а не от даты завершения.
- Пример: коммуналка 23-го, завершена 25-го → следующая `next_date` = 23-е следующего месяца.

## 5. Вычисление `next_date`

### 5.1. Fixed — Daily

```
next_date = предыдущий next_date + interval дней
```

Если предыдущий `next_date` в прошлом (задача просрочена), вычисляется ближайшая будущая дата, кратная интервалу.

### 5.2. Fixed — Weekly

```
next_date = ближайший день из weekdays[], >= предыдущий next_date + 1 день,
            с учётом interval недель
```

Логика:

1. Если в текущей неделе есть ещё дни из `weekdays[]` после текущего дня — берём ближайший.
2. Иначе — переходим на `interval` недель вперёд и берём первый день из `weekdays[]`.

При первом создании (нет предыдущего `next_date`): `next_date` = ближайший день из `weekdays[]`, начиная с завтра.

### 5.3. Fixed — Monthly

```
next_date = day_of_month число следующего подходящего месяца
```

- Если `day_of_month` > количество дней в месяце → используется последний день месяца.
- «Следующий подходящий месяц» = текущий месяц next_date + `interval`.

### 5.4. Fixed — Yearly

```
next_date = month_and_day.day / month_and_day.month следующего подходящего года
```

- Следующий подходящий год = текущий год next_date + `interval`.
- Для 29 февраля в невисокосный год → 28 февраля.

### 5.5. After Completion

```
next_date = completed_at (дата) + delay_days дней
```

## 6. Примеры

### 6.1. Ежедневный обзор задач

> Каждый день задача появляется в "today".

```json
{
  "type": "fixed",
  "frequency": "daily",
  "interval": 1,
  "target_box": "today",
  "advance_days": 0
}
```

| Действие                       | Результат                                                                              |
| ------------------------------ | -------------------------------------------------------------------------------------- |
| 13 апреля: завершаю задачу     | Клон создаётся: `next_date = 14 апреля`, `appear_date = 14 апреля`, `is_hidden = true` |
| 14 апреля: открываю приложение | `is_hidden → false`, задача в коробке "today"                                          |

### 6.2. Еженедельный обзор по понедельникам

> Каждый понедельник задача появляется в "today".

```json
{
  "type": "fixed",
  "frequency": "weekly",
  "interval": 1,
  "weekdays": [1],
  "target_box": "today",
  "advance_days": 0
}
```

| Действие                        | Результат                                                                         |
| ------------------------------- | --------------------------------------------------------------------------------- |
| Понедельник 13 апреля: завершаю | Клон: `next_date = 20 апреля (пн)`, `appear_date = 20 апреля`, `is_hidden = true` |
| Понедельник 20 апреля: открываю | `is_hidden → false`, задача в "today"                                             |

### 6.3. Коммуналка 23-го числа

> Каждое 23-е число задача появляется в "today".

```json
{
  "type": "fixed",
  "frequency": "monthly",
  "interval": 1,
  "day_of_month": 23,
  "target_box": "today",
  "advance_days": 0
}
```

| Действие                         | Результат                                                              |
| -------------------------------- | ---------------------------------------------------------------------- |
| 23 апреля: завершаю              | Клон: `next_date = 23 мая`, `appear_date = 23 мая`, `is_hidden = true` |
| 25 апреля: завершаю (просрочено) | Клон: `next_date = 23 мая` (от расписания, не от даты завершения)      |

### 6.4. Полить цветы через 4 дня

> Через 4 дня после полива задача появляется в "today".

```json
{
  "type": "after_completion",
  "delay_days": 4,
  "target_box": "today",
  "advance_days": 0
}
```

| Действие            | Результат                                                                    |
| ------------------- | ---------------------------------------------------------------------------- |
| 13 апреля: завершаю | Клон: `next_date = 17 апреля`, `appear_date = 17 апреля`, `is_hidden = true` |
| 17 апреля: открываю | `is_hidden → false`, задача в "today"                                        |

### 6.5. Парикмахерская раз в месяц

> Через 3 недели после завершения задача появляется в "week".

```json
{
  "type": "after_completion",
  "delay_days": 21,
  "target_box": "week",
  "advance_days": 0
}
```

| Действие            | Результат                                                            |
| ------------------- | -------------------------------------------------------------------- |
| 13 апреля: завершаю | Клон: `next_date = 4 мая`, `appear_date = 4 мая`, `is_hidden = true` |
| 4 мая: открываю     | `is_hidden → false`, задача в "week"                                 |

### 6.6. Прививка кошке раз в год

> За месяц до даты прививки задача появляется в "later".

```json
{
  "type": "fixed",
  "frequency": "yearly",
  "interval": 1,
  "month_and_day": { "month": 4, "day": 13 },
  "target_box": "later",
  "advance_days": 30
}
```

| Действие                 | Результат                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------- |
| 13 апреля 2026: завершаю | Клон: `next_date = 13 апреля 2027`, `appear_date = 14 марта 2027`, `is_hidden = true` |
| 14 марта 2027: открываю  | `is_hidden → false`, задача в "later"                                                 |

## 7. UI: фильтр скрытых задач

### 7.1. Значок глазика в нижнем фильтре

В нижней панели фильтров добавляется значок **глаза** (toggle):

- **Выключен (по умолчанию):** скрытые задачи не отображаются.
- **Включён:** скрытые задачи видны с визуальным отличием:
  - Приглушённый цвет текста (opacity ~50%).
  - Иконка расписания (🔄 или аналог) рядом с названием.
  - Подпись с датой появления: «Появится 14 марта».

### 7.2. Индикатор повторения на задаче

Все задачи с `repeat_rule` (и видимые, и скрытые при включённом toggle) отображают маленькую иконку повторения (🔄) — чтобы пользователь видел, что задача повторяющаяся.

## 8. UI: настройка повторения

### 8.1. Точка входа

В экране редактирования задачи — поле **«Повторение»** (или иконка 🔄). По нажатию открывается экран/модалка настройки.

### 8.2. Экран настройки повторения

**Шаг 1: Тип**

Два варианта на выбор:

- **По расписанию** (fixed)
- **После завершения** (after_completion)

**Шаг 2a: Параметры для «По расписанию»**

- **Частота:** Daily / Weekly / Monthly / Yearly (сегментированный контрол).
- **Интервал:** «Каждые \_\_\_ [дн./нед./мес./лет]» — числовой ввод, по умолчанию 1.
- **Для Weekly:** мультивыбор дней недели (Пн—Вс), кнопки-чипы.
- **Для Monthly:** выбор числа месяца (1—31), числовой ввод или пикер.
- **Для Yearly:** выбор даты (день + месяц), два пикера.

**Шаг 2b: Параметры для «После завершения»**

- **Через:** «\_\_\_ дней после завершения» — числовой ввод.

**Шаг 3: Куда поместить**

- **Коробка:** Today / Week / Later — сегментированный контрол.
- **Заранее:** «Показать за \_\_\_ дней до даты» — числовой ввод, по умолчанию 0.

## 9. Пограничные случаи

### 9.1. Месяцы с разным количеством дней

Если `day_of_month = 31`, а в месяце 30 дней (или 28/29) — задача создаётся на **последний день месяца**.

Пример: `day_of_month: 31` → 31 января, 28 февраля, 31 марта, 30 апреля...

### 9.2. Yearly: 29 февраля

Если `month_and_day: { month: 2, day: 29 }`, а год невисокосный — задача создаётся **28 февраля**.

### 9.3. Weekly: несколько дней

Если `weekdays: [1, 3, 5]` (Пн, Ср, Пт) — при завершении в понедельник следующий `next_date` = ближайшая среда. При завершении в пятницу — следующий понедельник (с учётом `interval`).

### 9.4. Удаление повторяющейся задачи

- **Удаление текущего экземпляра** (soft delete):
  - Если у задачи есть копии (по `original_task_id`), они переназначаются на новый оригинал
  - Первая активная копия становится новым корнем цепочки
  - Все остальные копии обновляют `original_task_id` на ID нового корня
  - Исходная задача помечается `is_deleted: true`
- **Удаление правила повторения**: пользователь снимает `repeat_rule` с задачи. Если есть скрытый клон — он тоже помечается `is_deleted: true`.
- **Удаление скрытого клона**: при включённом toggle пользователь может удалить ожидающий клон.

#### Пример переназначения при удалении:

**До удаления:**

- task-1: `original_task_id: ""`
- task-2: `original_task_id: "task-1"` (скрытая копия)
- task-3: `original_task_id: "task-1"` (скрытая копия)

**Пользователь удаляет task-1:**

**После удаления:**

- task-1: `is_deleted: true`
- task-2: `original_task_id: ""` ← новый оригинал
- task-3: `original_task_id: "task-2"` ← переназначена

**Результат:** Цепочка повторений сохраняется, task-2 становится новым корнем.

### 9.5. Редактирование повторяющейся задачи

При редактировании задачи с `repeat_rule`:

- Изменения **title, notes, goal, context, category** применяются к текущему экземпляру
- При следующем завершении эти изменения автоматически переносятся в скрытую копию (если она существует) или в новую копию
- Изменение **repeat_rule** — обновляет правило и пересоздаёт скрытый клон (удалить старый, создать новый с новыми параметрами)

**Механизм синхронизации изменений:**
Благодаря полю `original_task_id`, при завершении задачи система находит существующую скрытую копию и обновляет в ней все актуальные поля (name, description, goal_id, context_id, category_id, repeat_rule). Это гарантирует, что изменения не теряются.

### 9.6. Завершение скрытого клона

Если пользователь включил toggle, видит скрытый клон и завершает его — это допустимо. Создаётся новый клон по тем же правилам. `completed_at` = текущая дата.

### 9.7. Первое создание повторяющейся задачи

Когда пользователь добавляет `repeat_rule` к обычной задаче:

- Задача остаётся в текущей коробке, `is_hidden: false`.
- `next_date` вычисляется на основе текущей даты и правила.
- `appear_date` = `next_date` − `advance_days`.
- Клон будет создан при завершении этой задачи.

### 9.8. UI: Открытие панели редактирования

**При завершении повторяющейся задачи:**

- Скрытая копия создаётся в фоне с `is_hidden: true`
- Панель редактирования **НЕ открывается** для скрытой копии
- Пользователь не видит скрытую задачу до наступления `appear_date`

**При ручном копировании задачи (кнопка Duplicate):**

- Создаётся обычная копия с `is_hidden: false`
- Поле `original_task_id` остаётся пустым (нет связи с оригиналом)
- Панель редактирования **открывается** для новой копии
- Если оригинал был повторяющимся, копия наследует `repeat_rule`, но становится независимой задачей

**Реализация:**

- `useTasks.completeTask()` и `useTaskMutations.completeTask()` возвращают `null` вместо ID, если созданная копия скрыта
- `InboxPage.handleDuplicateTask()` и `GoalDetailPage.onDuplicate()` открывают панель редактирования после создания копии

## 10. Синхронизация

### 10.1. Хранение

- `repeat_rule` хранится как JSON-строка в ячейке Google Sheets.
- `is_hidden`, `next_date`, `appear_date` — отдельные колонки в листе Tasks.
- Пустые значения = пустая строка `""`.

### 10.2. Конфликты

- Клон создаётся на клиенте при завершении задачи.
- При push клон отправляется как новая запись (статус `created`).
- **Предотвращение дубликатов:** благодаря полю `original_task_id`, при завершении задачи система проверяет наличие существующей скрытой копии. Если копия найдена — она обновляется, а не создаётся новая.
- При конфликте (два устройства завершили одну задачу одновременно) — last-write-wins по `updated_at`. Возможны дубликаты только при race condition, но они минимизированы благодаря проверке по `original_task_id`.

### 10.3. Раскрытие скрытых задач

- Выполняется **на клиенте** при открытии приложения и после pull.
- Изменение `is_hidden` порождает push (version +1).

{"type":"fixed","frequency":"daily","interval":1,"target_box":"today","advance_days":0}

```

```

Пустая строка `""` = задача не повторяется.

## 12. Предотвращение дубликатов повторяющихся задач

### 12.1. Проблема

Если пользователь завершает повторяющуюся задачу, затем возвращает её в незавершённое состояние и завершает снова — без специальной логики создастся дубликат скрытой копии.

### 12.2. Решение: поле `original_task_id`

Все копии одной повторяющейся задачи связаны через поле `original_task_id`:

**Правила заполнения:**

1. **Обычные задачи:** `original_task_id = ""`
2. **Скрытые копии:** `original_task_id = task.original_task_id || task.id`
   - Если завершаем скрытую копию — наследуем её `original_task_id`
   - Если завершаем обычную задачу — берём её `id`
3. **При раскрытии:** `original_task_id` НЕ меняется

### 12.3. Алгоритм при завершении

```typescript
// 1. Определяем ID для поиска
const searchId = task.original_task_id || task.id;

// 2. Ищем существующую скрытую копию
const existingHiddenTask = findHiddenRecurringTask(searchId);

// 3. Если найдена — обновляем, иначе создаём новую
if (existingHiddenTask) {
  updateTask(existingHiddenTask.id, {
    name: task.name,
    description: task.description,
    goal_id: task.goal_id,
    context_id: task.context_id,
    category_id: task.category_id,
    repeat_rule: task.repeat_rule,
    next_date: calculatedNextDate,
    appear_date: calculatedAppearDate,
    box: rule.target_box,
  });
} else {
  createRecurringCopy(task, {
    original_task_id: searchId,
    is_hidden: true,
    next_date: calculatedNextDate,
    appear_date: calculatedAppearDate,
    box: rule.target_box,
  });
}
```

### 12.4. Цепочка повторений

**Пример цепочки:**

- task-1: `original_task_id: ""` (оригинал)
- task-2: `original_task_id: "task-1"` (скрытая копия)
- task-2 раскрывается: `original_task_id: "task-1"` (не меняется)
- task-2 завершается → создаётся task-3: `original_task_id: "task-1"`

Все копии связаны с одним оригиналом через `original_task_id`.

### 12.5. Преимущества

✅ Невозможно создать дубликаты при возврате задачи в незавершённое состояние
✅ Изменения в имени, описании, связях автоматически переносятся в скрытую копию
✅ Работает для всех типов `repeat_rule` (fixed и after_completion)
✅ Легко найти все копии одной задачи для отладки
✅ При удалении оригинала цепочка сохраняется (копии переназначаются на новый корень)
