# ADR: BDD E2E Tests via playwright-bdd

**Status:** Accepted
**Date:** 2026-05-05
**Context:** Implementing NFR scenarios (accessibility, responsive, UX polish) from Gherkin feature files as executable E2E tests

---

## Problem

Feature files `*_e2e.feature` describe scenarios requiring a real browser: keyboard focus, aria-labels, responsive layout, CSS animations. We need a way to:
- Turn Gherkin specifications into executable Playwright tests
- Maintain traceability between requirements (NFR-A1, UX4...) and tests
- Run tests in CI for regression control
- Not break existing unit BDD (vitest-cucumber) and e2e (Playwright) tests

---

## Decision

Use **playwright-bdd** — a library that generates Playwright test files from Gherkin feature files.

### File Structure

```
packages/client/
├── playwright.bdd.config.ts              # Separate config for BDD e2e
├── src/test/features/<feature>/
│   ├── *_e2e.feature                     # Gherkin specification (requires browser)
│   ├── *_unit.feature                    # Gherkin specification (unit level)
│   └── steps/
│       ├── *_e2e.steps.ts                # Step definitions (playwright-bdd)
│       └── *_unit.steps.ts               # Step definitions (vitest-cucumber)
├── .features-gen/                        # Auto-generated by playwright-bdd (in .gitignore)
```

### Naming Convention

- `*_e2e.feature` — scenarios requiring a real browser (playwright-bdd)
- `*_unit.feature` — scenarios verified by unit tests (vitest-cucumber)
- `*_e2e.steps.ts` — step definitions for playwright-bdd
- `*_unit.steps.ts` — step definitions for vitest-cucumber

### Separate Config

`playwright.bdd.config.ts` does not interfere with the existing `playwright.config.ts`:
- `playwright.config.ts` — regular e2e tests (`src/test/e2e/*.spec.ts`)
- `playwright.bdd.config.ts` — BDD e2e from feature files

### Requirements Traceability

| Layer                    | Mechanism                                      |
|--------------------------|------------------------------------------------|
| Feature -> Proposal      | Tags `@add-goal-focus @NFR-A1` in Gherkin      |
| Steps -> Feature         | Pattern matches step text                      |
| Steps -> Requirement     | Comment `// Verifies NFR-A1 of add-goal-focus` |
| CI report -> Requirement | Cucumber HTML reporter shows tags              |

### Tag Filtering

```bash
# Accessibility only
pnpm test:bdd:a11y   # --tags "@NFR-A1 or @NFR-A2 or @NFR-A3"

# Entire feature
npx bddgen --tags "@add-goal-focus" -c playwright.bdd.config.ts
```

### Scripts

```
test:bdd       — generate + run all BDD e2e tests
test:bdd:a11y  — accessibility only (NFR-A*)
test:all       — unit + BDD e2e + regular e2e
```

---

## Rationale

### Why playwright-bdd, not plain Playwright

- Feature file remains the single source of truth (specification = test)
- Gherkin tags (`@NFR-A1`) are natively used for run filtering
- Cucumber HTML reporter shows scenario pass/fail with tags
- Step definitions are reused across scenarios

### Why not vitest-cucumber for e2e

- vitest-cucumber runs in jsdom — no real focus, aria, layout
- NFR-A (accessibility), NFR-R (responsive), UX4 (animations) require a real browser

### Why a separate config instead of extending playwright.config.ts

- Separation of concerns: BDD scenarios from feature files vs free-form e2e tests
- Different glob patterns for `testDir`
- Can be run independently or together

### Why feature and steps in the same folder

- The project already uses the convention `src/test/features/<feature>/steps/`
- The `_e2e`/`_unit` suffix clearly separates the two runners
- Feature file next to step definitions — easy to navigate

---

## Alternatives

### Plain Playwright without Gherkin

**Pros:** simpler, no playwright-bdd dependency, no generation step
**Cons:** feature file becomes dead documentation, direct specification-to-test link is lost, no Cucumber reports with tags
**Verdict:** Rejected. The value of BDD is precisely in executable specifications.

### Single playwright.config.ts config

**Pros:** one configuration file
**Cons:** testDir conflict (regular spec.ts vs generated from feature), harder to run separately
**Verdict:** Rejected. Two configs are cleaner.

---

## Dependencies

- `playwright-bdd` (devDependency)
- `.features-gen/` and `cucumber-report/` in `.gitignore`

---

## CI Integration

```yaml
- run: pnpm test          # Unit + vitest-cucumber BDD
- run: pnpm build
- run: pnpm test:bdd      # Playwright BDD (NFR e2e)
- run: pnpm test:e2e      # Other e2e tests
```
